# Meme Cam

Десктопний додаток для Windows: камера з мем-лінзами. Перша лінза — **«лазерні очі»**:
з зіниць б'є світло, яке слідкує за обличчям у реальному часі.

Electron + React + TypeScript, ефекти на WebGL2, трекінг обличчя — MediaPipe локально
(інтернет потрібен лише один раз, щоб завантажити модель).

## Запуск

```bash
npm install
npm run setup   # один раз: качає модель обличчя і кладе wasm
npm run dev     # режим розробки з гарячим перезавантаженням
```

Зібрати і запустити як звичайний застосунок:

```bash
npm run build
npm start
```

## Збірка застосунку

```bash
npm run make:icon   # готує іконку
npm run dist
```

**Іконка.** Якщо покласти `build/icon-source.png`, він стане іконкою застосунку.
Інакше береться намальований `build/icon.svg`. Зображення вписується у квадрат
512×512 зі збереженням пропорцій і розкладається одразу в двох місцях: для
інсталятора (`build/icon.png`) і для шапки самого додатка
(`src/renderer/public/icon.png`).

У теці `release/` з'являться два файли:

| Файл | Що це |
| --- | --- |
| `Meme Cam Setup 0.1.0.exe` | інсталятор: ярлик на робочому столі, запис у «Програми» |
| `MemeCam-portable-0.1.0.exe` | один файл, нічого не встановлює — просто запусти |

> **Якщо збірка падає на `Cannot create symbolic link`** — це не наш код. Пакет
> `winCodeSign` від electron-builder містить macOS-симлінки, а Windows без режиму
> розробника їх створювати не дає. Лікується розпакуванням вручну без теки `darwin`
> (вона потрібна лише для збірки під Mac):
>
> ```bash
> CACHE="$LOCALAPPDATA/electron-builder/Cache/winCodeSign"
> ./node_modules/7zip-bin/win/x64/7za.exe x "$CACHE/<завантажений>.7z" \
>   -o"$CACHE/winCodeSign-2.6.0" -y "-x!darwin"
> ```

> **Якщо запускаєш з терміналу VS Code** — усе вже враховано. VS Code ставить у оточення
> `ELECTRON_RUN_AS_NODE=1`, через що Electron стартував би як звичайний Node і вікно не
> з'явилося б. `scripts/run-electron.mjs` прибирає цю змінну перед запуском.

## Трансляція в Discord

Кнопка «Транслювати в Discord» віддає кадр у систему як звичайну веб-камеру.
У Discord (Zoom, Meet, будь-де) обери камеру **Meme Cam**.

Кадр пакується в NV12 прямо на відеокарті ([NV12_FS](src/renderer/src/gl/shaders.ts)),
одним `readPixels` знімається з GPU і кладеться у спільну пам'ять, звідки його забирає
драйвер камери.

Камера віддає **1280×720 при 60 кадрах/с**. Режим 30 кадрів/с лишився другим
варіантом у списку форматів — застосунок на тому боці може обрати його сам.

Драйверів підтримується два, вибір у випадаючому списку поруч із кнопкою:

| Пристрій | Коли потрібен |
| --- | --- |
| **Meme Cam** | свій DirectShow-фільтр, окремий пристрій у системі. Основний варіант |
| **OBS Virtual Camera** | запасний: використовує камеру, яку ставить OBS |

### Власний драйвер камери

У `native/memecam-filter` лежить DirectShow source filter на C++ — саме він робить
«Meme Cam» окремим пристроєм, незалежним від OBS. Написаний без DirectShow BaseClasses:
їх прибрали з сучасного Windows SDK, тому потрібні інтерфейси (`IBaseFilter`, `IPin`,
`IAMStreamConfig`, `IKsPropertySet`) реалізовані вручну.

Дві речі, які тут варто знати:

**Реєстрація не потребує адміністратора.** `DllRegisterServer` пише не в HKLM, а в
`HKCU\Software\Classes`. Windows зводить обидві гілки в `HKEY_CLASSES_ROOT`, тож камеру
бачать усі застосунки користувача, зате встановлення проходить без запиту прав.
Кнопка «встановити» в додатку робить саме це.

**Бібліотека реєструється не на місці, а з копії в `%APPDATA%\meme-cam\driver`.**
Портативна збірка розпаковується у теку в `Temp`, яка зникає після закриття додатка.
Зареєструвавши її звідти, отримали б у системі камеру, що вказує в порожнечу: пристрій
у списку є, а завантажити його неможливо. Тека даних користувача переживає і закриття,
і оновлення, тому [registerFilter](src/main/filterRegistration.ts) спершу копіює
бібліотеку туди й реєструє вже копію.

**Ім'я копії містить номер версії** (`memecam-filter-0.2.0.dll`). Windows тримає
зареєстровану бібліотеку завантаженою в кожному застосунку, який колись перелічував
камери, тож перезаписати чи навіть перейменувати її при оновленні не вийде. Нова версія
просто лягає поруч під новим іменем, а стара знімається з реєстрації й видаляється,
коли її нарешті відпустять.

**Оновлення застосунку не має ламати камеру.** Інсталятор перед оновленням запускає
деінсталятор попередньої версії, і той зняв би реєстрацію. Тому в
[installer.nsh](build/installer.nsh) зняття загорнуте в `${ifNot} ${isUpdated}`, а
додаток при старті ще й перевіряє позначку `driver-installed`: якщо камеру колись
ставили, а зараз вона зникла або застаріла — реєструє заново, мовчки.

**Своя черга кадрів.** Фільтр читає спільну пам'ять `MemeCamVideo`, а не
`OBSVirtualCamVideo`. Тому наша камера і камера OBS можуть працювати одночасно й не
заважають одна одній.

Збірка:

```bash
npm run build:filter            # потрібні VS Build Tools з компонентом C++ і Windows SDK
npm run build:filter -- --force # перезібрати навіть якщо сирці не мінялись
```

Збірка пропускається, якщо сирці не змінювались. Це не оптимізація, а потреба: Windows
тримає зареєстровану бібліотеку завантаженою в кожному застосунку, який колись перелічував
камери, і перезбирання впало б на «файл зайнятий».

Перевірити камеру без Discord:

```bash
npm run test:vcam 30 memecam    # жене в камеру кольорові смуги
ffmpeg -f dshow -i video="Meme Cam" -frames:v 1 -update 1 out.png
```

### Чому трансляція не гальмує

Дві речі, які тут неочевидні й обидві коштували продуктивності:

**Приспане вікно.** Щойно користувач перемикається в Discord, наше вікно стає невидимим,
і Chromium дроселює `requestAnimationFrame` приблизно до кадру на секунду. Камера
перетворюється на слайдшоу саме тоді, коли вона потрібна. Лікується двома заходами разом:
ключі `disable-renderer-backgrounding` і компанія в [main](src/main/index.ts) плюс
`backgroundThrottling: false`. Додатково під час трансляції цикл рендеру веде **таймер**,
а не rAF — таймер не залежить від того, чи хтось дивиться на вікно.

**Синхронне знімання кадру.** `readPixels` прямо в масив зупиняє CPU, доки GPU не
домалює. Замість цього кадр знімається через пару pixel buffer object з огорожею:
читання повертається одразу, а дані забираються наступного такту. Заміряно на 720p:
**1.21 мс проти 0.3 мс** на кадр, усі кадри доходять.

Поточну вартість кадру видно на плашці «● у Discord» під час трансляції.

Обмеження, про які варто знати:

- Додаток має лишатися відкритим, поки йде трансляція: спільна пам'ять живе рівно
  стільки, скільки живе процес. Коли додаток закритий, камера показує чорний кадр.
- Запасний варіант через OBS вимагає встановленого OBS і ділить з ним спільну пам'ять —
  якщо запустити віртуальну камеру ще й в OBS, вони заважатимуть одне одному.
- Формат черги неофіційний, узятий зі структури `queue_header` у вихідниках OBS.
  Оновлення OBS теоретично може його змінити; тоді камера не запуститься, але
  аварії не буде — побачиш повідомлення про помилку.
- Додаток має лишатися відкритим, поки йде трансляція.

## Маски

Маска — це список шарів у [registry.ts](src/renderer/src/masks/registry.ts). Шар буває
двох видів: **накладка** (SVG, посаджений на точки обличчя) або **лінза** (параметри
шейдерних ефектів). Нова маска додається кількома рядками:

```ts
{
  id: 'king', name: 'Король', icon: '👑',
  layers: [head('crown.svg', 1.15, [0, 0.62])]
}
```

Накладка кріпиться до **двох точок обличчя**: відстань між ними задає масштаб, а їхній
напрямок — кут. Тому маска сама росте, коли підходиш до камери, і хилиться разом з
головою, без жодного коду. Вісь примусово розвертається праворуч — інакше дзеркалення
селфі міняло б точки місцями і перевертало накладку.

Асети — SVG, їх растеризує сам Chromium, тому вони лишаються різкими на будь-якій
роздільності.

## Голос

Мікрофон проходить через `AudioWorklet` ([voice.js](src/renderer/public/worklets/voice.js)) —
окремий аудіопотік, тож звук не заїкається, навіть коли інтерфейс завантажений.
Сім пресетів: «Сповільнений», «Демон», «Бурундук», «Робот», «Печера», «Рація».

**«Сповільнення» тут — це зсув тону вниз, а не розтяг часу.** Справжнє сповільнення
в лайві неможливе: розтягнутий вихід довший за вхід, і затримка росла б нескінченно.
Зсув тону звучить так само низько й тягуче, але затримка лишається сталою — близько
20-40 мс.

Зсув тону зроблено на затримці зі змінною позицією читання. Позиція повзе відносно
запису й перестрибує, доповзши до краю вікна; щоб стрибок не було чути, читаємо двома
голосами, зсунутими на пів вікна, і зважуємо трикутним вікном — гучність кожного падає
до нуля рівно там, де він стрибає.

### Як віддати голос у Discord

Тут є межа, яку варто розуміти: **віртуальний мікрофон у Windows — це драйвер режиму
ядра**, а такі вимагають підпису WHQL. Тому своїм драйвером, як для камери, тут не
обійтися.

Робочий шлях — безкоштовний віртуальний аудіокабель, наприклад
[VB-CABLE](https://vb-audio.com/Cable/). Після встановлення:

1. У Meme Cam обери вихід **CABLE Input**
2. У Discord обери мікрофон **CABLE Output**

Без кабелю голос іде у вибраний вихід, тобто ти чуєш себе сам — зручно, щоб підібрати
ефект.

## Оновлення

Кнопка з дзвіночком у шапці відкриває «Що нового»: історію версій з поділом на
додано / змінено / виправлено / видалено, а зверху — стан перевірки оновлень.
Історія лежить у [changelog.ts](src/renderer/src/changelog.ts) і оновлюється разом
з версією в `package.json`.

Оновлення тягнуться з релізів GitHub. Щоб випустити нову версію:

1. Підніми `version` у `package.json` і додай запис у `changelog.ts`
2. Встав токен GitHub у файл `.env` (скопіюй його з `.env.example`):

   ```
   GH_TOKEN=ghp_твій_токен
   ```

   Токен: Settings → Developer settings → Personal access tokens →
   Tokens (classic) → Generate new → scope **`repo`**

3. ```bash
   npm run publish
   ```

`.env` у git не потрапляє — про це подбає `.gitignore`. Перевірити можна так:
`git check-ignore -v .env`.

Репозиторій задано в полі `build.publish` у `package.json`.

**Репозиторій має бути публічним.** Встановлений додаток перевіряє оновлення без
жодної авторизації — у нього немає твого токена, і з приватного репозиторію він
побачив би 404. Зашити токен у застосунок не можна: його елементарно дістати
з файлів.

У режимі розробки перевірка вимкнена свідомо — оновлювати нема чого.

## Перевірки

`tsc` не бачить ні GLSL, ні геометрії масок — тут потрібні свої перевірки. Обидві
піднімають приховане вікно Electron і працюють без камери:

| Команда | Що ловить |
| --- | --- |
| `npm run check:shaders` | помилки компіляції та лінкування кожної пари шейдерів у справжньому WebGL2. Входить у `npm run build` |
| `npm run check:masks` | посадку масок: рендерить їх на схематичному обличчі з відомими координатами і зберігає знімки. Видно перевороти, промахи зсуву, невірний масштаб |
| `npm run check:audio` | обробку голосу: подає чистий тон і міряє, чи зсув тону дав саме ту частоту |
| `npm run test:vcam` | тримає у віртуальній камері кольорові смуги. Перевіряти так: `ffmpeg -f dshow -i video="Meme Cam" -frames:v 1 -update 1 out.png` |

## Як влаштована лінза

MediaPipe дає 478 точок обличчя, з них потрібні дві — центри зіниць (індекси 468 і 473) —
і матриця повороту голови. Ефект складається з трьох частин, які разом дають вигляд
з референсів:

| Складова | Що це | Коли видно |
| --- | --- | --- |
| **Ядро** | яскрава пляма в самій зіниці | завжди |
| **Штрих** | горизонтальний анаморфний відблиск | завжди, головне в кадрі анфас |
| **Промінь** | направлений конус уздовж погляду | коли голова відвернута від камери |

Промінь гасне, коли людина дивиться прямо в об'єктив — тоді він летить у камеру, і збоку
його не видно. Це не баг, а те, чому анфас на референсі виглядає як спалах, а не як промінь.
Сила береться з `dirStrength` у [FaceTracker.ts](src/renderer/src/face/FaceTracker.ts).

Чіткість — це показник степеня в поперечному профілі `exp(-(d/w)^k)`. При `k = 2` виходить
звичайний гаус, тобто м'яке розмите пасмо; при `k = 6` і вище — пласка вершина з різким
спадом, тобто справжній лазер. Всередині ще одне тонше гаряче ядро — без нього промінь
читається як підсвічена смуга, а не як розряд.

Поверх — атмосфера: **низовий дим** знизу і **блискавки** згори. Дим — FBM-шум з доменним
варпом (саме варп робить клуби, а не рівні смуги), розряд — ламана з трьох октав шуму плюс
обвідна з різким фронтом і повторним ударом. Обидва малюються за один прохід з
преммультиплікованою альфою: дим змішується як напівпрозорий шар, а розряд з `alpha = 0`
лягає чисто адитивно.

Пайплайн рендеру — [LensRenderer.ts](src/renderer/src/gl/LensRenderer.ts):

```
відео -> сцена (грейд) -> дим і блискавки -> промені (адитивно)
      -> відбір яскравого -> два ланцюги розмиття -> композит з ACES-тонмапом
```

Дим і блискавки стоять до відбору яскравого — тому розряди самі підхоплюють bloom.

Проміжні буфери — `RGBA16F`, якщо драйвер дає `EXT_color_buffer_float`. Це важливо: bloom
має брати справді перепалені значення, інакше сяйво виходить пласким.

## Що далі

Зроблено: лінза, фото, дим і блискавки, система масок, трансляція в Discord. Наступне:

**Фаза 2, звук.** Мікрофон -> Web Audio `AudioWorklet` -> навушники.

Важливо: справжнє сповільнення звуку в лайві неможливе. Якщо розтягувати час у 2 рази,
вихід стає довшим за вхід, і затримка росте нескінченно — через хвилину чуєш те, що сказав
пів хвилини тому. Тому:

- **живий моніторинг** — pitch-shift вниз (голос низький, затримка стала ~20–40 мс)
- **записане відео** — справжнє сповільнення 0.5x, там пітч падає сам собою

Звучить однаково «замедленно», механізми різні.

**Фаза 3, відео.** `canvas.captureStream()` + `MediaRecorder`, потім сповільнення доріжок.
Ефект уже намальований на canvas, тож у запис він потрапляє готовим.
